# Math functions: bit for bit like current V8

**Decision.** `Math.exp/log/sin/cos/tan/asin/acos/atan2` go through `scrust_value::jsmath`, which on native targets calls vendored CORE-MATH functions (`crates/scrust-value/csrc/core-math`, MIT, compiled by `build.rs`). Their results are correctly rounded. `Math.atan` is a Rust port of LLVM libc's `atan` (`src/llvm_atan.rs`, Apache-2.0 WITH LLVM-exception), the implementation V8 uses: it has no accurate second pass, so near halfway cases it is off by one ulp from the correctly rounded value, and CORE-MATH would differ from the browser there. The port uses fused multiply-add (`f64::mul_add`), as LLVM libc compiled for arm64 does. `x ** y` follows `v8::internal::math::pow`: the ECMAScript special cases, `y == 2` as `x * x`, `y == 0.5` as `sqrt(x + 0)`, otherwise the platform `pow` (the base is passed through `black_box`, because LLVM rewrites `pow(10, y)` into `exp10(y)`). `10 ^ n` for integer `|n| <= 22` still comes from an exact table, which agrees with the platform `pow`. The wasm build keeps the `libm` crate.

**Why.** The reference is TurboWarp in a current browser (see [turbowarp.md](turbowarp.md)). V8 now routes these functions to LLVM libc, whose results are correctly rounded except for `atan`, and on macOS `Math.pow` / `**` call the platform `pow` (`--use-std-math-pow`). The `libm` crate differed in the last bit on 0.4-10 % of inputs (exp 9.7 %, pow 9.5 %, acos 7.9 %, asin 5.7 %, sin/cos/tan 3-4 %), which 3D engines turn into visible drift.

**Measured.** 20,000 random inputs per function in Chrome 156 (V8, macOS arm64), typical Scratch ranges (`exp` on [-50, 50], `log` on [e^-10, e^30], trig on degree arguments in [-1000, 1000], `atan` on [-100, 100], `asin/acos` on [-1, 1], `10 ** x` on [-10, 10]): all of Chrome's `exp/log/sin/cos/tan/asin/acos` results equal the correctly rounded value (mpmath, 200 bits), its `10 ** x` equals Apple's `pow` on every input, and `jsmath` reproduces all results bit for bit. `atan` was correctly rounded on all random samples too, but projects hit inputs where it is not (for example `atan(0x3ff0fffb8e896293)` is `…ad2c` in Chrome, correctly rounded `…ad2d`); the port matches those and 120,000 recorded samples (`tests/atan_v8.rs`). `atan2` matches 100,000 samples (integer and fractional sprite offsets, wide magnitudes, signed zeros and infinities).

**Limits.** Browsers on other platforms may differ for `pow`, and for `atan` on CPUs without FMA. The graphic-effect formulas emulating GLSL (`fisheye`, `whirl`) keep `libm`, since the GPU does not round correctly either.
